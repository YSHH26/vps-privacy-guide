# 用提供商 API 核验换系统前后的主机

KiwiVM 官网说，API 文档要登录控制面板以后才能看到。公开页面上没有完整的接口说明，网上流传的第三方副本也不能当成现在的官方文档。所以这一页把**实际看到的 API 行为**和**还没执行过的操作**分开记。

来源：[官方 API 介绍](https://bandwagonhost.com/dubai-vps.php)、[官方 API 服务](https://api.64clouds.com/)。请求发到 `https://api.64clouds.com/v1/`，凭据通过 curl 的标准输入传进去，不会出现在进程参数或聊天里。服务商的实例标识和 API Key 只存在私有文件里。

## 已经实际看到的读取能力

2026-11-17，在被授权测试的实例上：官方的 `basicShell/exec` 收到没带 `command` 的请求时，返回 `error=255` 和 `No command supplied`；带上只读命令时返回 `error=0`，`message` 是一段包含命令输出的字符串。通过它读到的 boot ID 和 Ed25519 主机公钥，跟现有可信 SSH 连接读到的一样。`getLiveServiceInfo` 返回 `ve_status=running` 和实际的 `ssh_port`。

这些只是这台实例这一次的实际响应，不代表所有虚拟化环境、所有系统模板都一样。尤其不能因为读取成功了，就提前说停机、换系统或新系统重新接入也都没问题。

## 换系统之前，先留一份可信的对照

在本机运行：

```sh
python3 scripts/vps.py --state private/target.json provider-proof
```

它先核对 API 凭据里的 VEID 和目标是不是同一台，再看 `getServiceInfo` 里的公网 IP 和 KVM 类型、`getLiveServiceInfo` 里的 IP、运行状态和 SSH 端口，然后读取能装的系统列表和服务商那边的 SSH 公钥库。

接着它给这次调用生成一个随机标记，通过官方的 `basicShell/exec` 只读地取回这个标记、boot ID 和主机公钥。返回的内容必须和这次的标记、预期格式完全对上，再跟现有严格校验过的 SSH 连接读到的值比较。旧系统上建不起可信的 SSH 对照时，这一步会停下，不会自己接受一个不认识的指纹。

成功以后，它把下面这些写进权限 600 的私有文件：

- `provider-proof.json`：API 来源、目标指纹、采集时间、随机标记的摘要、boot ID、实际端口和公钥。
- 目标状态里的 `provider_capabilities`：哪些读取接口和字段实际验证过、可信的 SSH 对照，以及停机、换系统、写入公钥库各自的状态。
- `available-os.json`：服务商这次返回的系统列表。

这份读取证明一小时内有效，过了就不能拿来换系统。目标不对、来源不对、过期、随机标记对不上，或者主机资料变了，都会停下。系统模板必须从实际返回的列表里选。加密备份还是要确认能恢复；存了备份的 SHA256 的话，换系统前会边读边核对整个文件，文件变了就停下。

## 换系统以后，再拿一份新的证明

换系统还是一条单独的命令，要明确确认目标，见 [从零部署步骤](pilot.md)。停机、换系统和写入公钥库在第一次真正执行之前，都记成 `pending-live-test`；只有对应的请求真的成功了，才记下观察结果。换系统请求被接受，只说明服务商接了这个任务，不代表新系统或节点已经能用。

被授权的测试实例已经实际换过两轮系统。第一轮验证了三件事：`updateSshKeys` 能把公钥写进这台实例，`stop` 能让它进入停止状态，`reinstallOS` 接受镜像参数。两轮都通过服务商读回了新系统的资料，并严格校验了 SSH。第二轮换系统时 API 返回过错误码 `788888`，意思是实例暂时被锁定；等服务商那边忙完，重新跑一次读取证明就行。锁定期间别重复发换系统请求。

等服务商显示新系统在运行了，再跑一次：

```sh
python3 scripts/vps.py --state private/target.json provider-proof
python3 scripts/vps.py --state private/target.json bootstrap
```

第二次证明通过服务商可信的 HTTPS API 拿到新的 boot ID 和新的主机公钥，不会先去建一条没核对过的 SSH 连接。它必须绑定同一台服务器和这一轮的换系统时间，boot ID 也必须和旧系统不一样。`bootstrap` 只认十五分钟以内的 API 主机证明，然后用这个公钥和实际端口单独核对 SSH。公钥登录还没恢复的话，可以用权限受限的密码文件，或者在本机安全地输入密码，见 [首次接入与密码引导](pilot.md)。

服务商的 API 暂时用不了时，可以照 [手工证明格式](pilot.md) 从可信的控制台读资料。不能退回去盲目相信 `ssh-keyscan`、关掉主机验证，或者拿旧公钥冒充新系统。

仓库入口用的是这一轮私有的 `known_hosts`。如果你用平时的 SSH 别名直接连，还是看到旧公钥的警告，先用仓库入口确认这一轮的主机证明和密钥连接没问题，再只替换你日常 SSH 文件里这台服务器的旧记录。新记录从这一轮验证过的私有主机文件里拿，其他服务器的记录不动。
