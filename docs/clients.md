# 把手机和电脑连上

先打开本机的账号页（一个 HTML 文件），找到你用的客户端对应的订阅。每个节点都单独试过以后，再去做 [IP 防泄露检查](leak-protection.md)。

四种订阅的内容不一样：

- **Clash 订阅**带分流规则：国内网站直连，AI 服务单独一组，其他走代理。
- **Surge 配置**最后的 FINAL 规则全部指向代理，没有分流。
- **Shadowrocket 和 v2rayN / v2rayNG 订阅**只有节点，走哪条路由用客户端自己的规则。

哪种订阅都不会替你打开整台设备的 TUN，也管不了断线时会不会变成直连。这两件事要在客户端里设置好，再检查一遍。

## 按客户端导入

| 客户端 | 默认使用 | 导入办法 |
| --- | --- | --- |
| Clash Verge Rev（Windows / macOS / Linux） | Reality、VLESS TLS、AnyTLS | 在「订阅」里粘贴 Clash 订阅地址并导入，模式选「规则」，打开「虚拟网卡模式」 |
| OpenClash（软路由） | 同上 | 「配置订阅」里添加同一个 Clash 订阅地址，关闭「在线订阅转换」，内核选 Meta |
| Shadowrocket（iPhone / iPad） | Reality、VLESS TLS、AnyTLS | 首页右上角「+」选「Subscribe」，粘贴 Shadowrocket 订阅地址；或扫描账号页里的二维码 |
| Surge | AnyTLS | 取账号页中的 Surge 格式订阅，按当前版本的远程配置/代理列表功能添加 |
| v2rayN | VLESS Reality、VLESS TLS | 在订阅分组添加 HTTPS 地址并更新；也可粘贴 VLESS 分享链接 |
| v2rayNG | VLESS Reality、VLESS TLS | 在订阅设置添加 HTTPS 地址并更新；也可扫描节点二维码或导入链接 |

Surge 用正式版就行，不需要支持 VLESS 的测试版。客户端认不出某个节点时，先看这个版本的应用和内核支不支持这个协议，别把它不认识的协议硬塞进配置。其他客户端能不能用 AnyTLS，也要看你装的版本。上表只说明大致怎么导入，具体菜单和最低能用的版本要在真机上测了才能记下来，没测过的版本不保证能用。

节点订阅和完整的 Surge 配置是两回事。下载到的是代理列表时，用客户端里对应的"代理列表"功能添加，别拿它覆盖你现有的整份配置。账号页里的 Clash/Mihomo 或 Shadowrocket 订阅也不能当 Surge 配置导入，它们的规则格式和含义都不一样，要分开检查。

添加好以后手动更新一次订阅，然后一个节点一个节点地选中，打开一个你确认过的 HTTPS 地址，看出口 IP 对不对。测的时候别开自动切换，不然一个坏节点会被另一个好节点盖住，你看不出来。测完把 Windows、Android、Mac 等设备上实际用的客户端和内核版本分别记下来。

## Clash 订阅里有什么

导入后你会看到三个分组：

- **PROXY**：平时走代理的流量用它。默认选 `AUTO`，也可以手动指定某一个节点。
- **AUTO**：按 Reality → VLESS TLS → AnyTLS 的顺序，前一个连不上就换下一个。逐个测节点时，在 PROXY 里手动选节点，别停在 AUTO。
- **AI**：OpenAI、Claude、Gemini 等海外 AI 服务单独走这一组，默认跟着 PROXY 走。想让 AI 固定用某个节点，在这里选。

规则从上往下匹配：服务器自己的 IP 和局域网直连 → 海外 AI 服务走 AI → Google Play 的国内缓存节点直连 → 国内域名和国内 IP 直连 → 腾讯的海外网络直连 → 剩下的全部走 PROXY。

其中有两条是为了解决常见问题专门加的：

- **Google Play 下载一直「等待中」**：国行手机下载应用时，Play 会分配北京、上海、广州的 Google 缓存节点。这些节点从国内直连没问题，从境外服务器连过去反而连不上。规则用的是上游 v2fly 数据里的 `google-play@cn`，只让这几个缓存节点直连，Play 商店的其他请求照样走代理。
- **微信图片发不出去、一直转圈**：微信很多连接不查域名，直接连服务器 IP。腾讯在香港、新加坡等地的服务器（AS132203）不在国内 IP 段里，本来会走代理，结果同一个微信一部分直连、一部分从海外出去。这条规则放在最后一条前面，只接住前面都没认出来、直接连 IP 的流量。

这两类流量本来就是故意让它直连的，对方会看到你本地的 IP，这不算泄露。不想这样的话，可以在客户端里把这两条规则覆盖掉。

DNS 用 fake-ip 模式。境外域名用 Cloudflare / Google 的 DoH 查询，查询本身也走代理；国内域名用阿里 / 腾讯的 DoH 直连查询。所有按 IP 匹配的规则都加了 `no-resolve`，匹配规则时不会先在本地查一遍域名，所以 DNS 泄露测试网站用的随机域名只会在代理那边被解析。代价是：没收进国内名单的国内网站会绕到代理上，还是能打开，只是慢一点。

规则数据（`geosite.dat`、`geoip.metadb`、`GeoLite2-ASN.mmdb`）由你的服务器每天从 MetaCubeX 的公开发布地址同步一份，客户端只从你自己的服务器下载，所以路由器在国内也不用直连 GitHub。下载或校验失败时，服务器继续用上一份。校验用的是同一来源发布的 sha256，只能发现下载过程中文件坏了，证明不了上游内容本身可信。

还有两点要注意：

- AnyTLS 需要较新的 Mihomo 内核。生成的配置用固定的 Mihomo 1.19.33 检查过，能正常解析；你实际用的 Clash Verge Rev / OpenClash 版本能不能连上，要在真机上测了记下来。
- 规则模式加上「虚拟网卡模式」（TUN）才能防住 WebRTC 泄露，只开系统代理不够，见 [WebRTC 泄露怎么修](webrtc.md)。Clash 设置里的 IPv6 开关保持打开，关掉以后 IPv6 流量可能直接绕过虚拟网卡。配置里的 DNS 不返回 IPv6 地址，服务器也不转发到 IPv6，所以开着它也不会让你从 IPv6 出去。

## 在线订阅要注意什么

订阅走 TCP 9443 的 HTTPS，真正生成订阅的后端只在服务器本机监听。客户端要开着证书验证，IP 证书要能按 IP 验证通过（证书里写的是 IP SAN）。Reality 占着 TCP 443，Nginx 不能再用这个端口。订阅地址里带一段很长的随机令牌，拿到链接的人就可能拿到你的节点，链接泄露了就要换令牌。

客户端自动更新订阅时，用账号页里给这个客户端生成的地址，别把一种格式的地址改个后缀冒充另一种。订阅只在你自己的服务器上生成和转换，不用第三方在线转换。分享链接、二维码和账号页 HTML 里都带着密钥，都别上传。

节点的连接地址应该是 VPS 的公网 IP 或证书上的域名，不能是 `127.0.0.1`、Docker 内部地址或本机 SSH 隧道地址。地址不对的话，回到 S-UI 检查用户关联、入站的发布地址、外部端口和客户端出站模板。

来源：[S-UI 订阅说明](https://github.com/alireza0/s-ui/wiki/Subscription-Service)。

## 用 sing-box 单独测试节点

[客户端模板](../examples/client.json) 只在本机 `127.0.0.1:1080` 开一个 HTTP/SOCKS 代理，默认选 Reality。它不开 TUN、不自动切换、不做 DNS 分流，节点出故障时也不会拦住流量。

把模板里的占位符全部换掉，再把 selector 的 `default` 依次改成 `reality`、`vless-tls`、`anytls`，每改一次重启一次，单独测。两条 VLESS 用的是同一个 S-UI 用户的 UUID，都开 Vision；Reality 要填公钥、short ID、server_name 和 Vision，服务端私钥不能放进客户端。VLESS TLS 和 AnyTLS 的证书身份要填对。

```sh
sing-box check -c private/client.json
sing-box run -c private/client.json
```

另开一个终端，用你自己确认过的 HTTPS 地址检查：

```sh
curl --proxy socks5h://127.0.0.1:1080 --max-time 20 https://example.com/
```

`socks5h` 会让代理那边去解析这次要访问的域名。这只能说明这一个请求走了代理，其他程序、DNS、IPv6、WebRTC 和退出客户端以后的情况都要分别测。三个节点都是 TCP 的，能不能转发 UDP 应用也要单独测，不能因为服务器没监听 UDP 就下结论。

## 出门前再检查一遍

如果你要带着设备去网络受限的地方，**出发前**把下面几件事做完。到了当地，下载客户端、打开这个仓库、登录服务商后台都可能变得很难。

1. 手机和电脑都装好客户端、导入订阅，在家里的网络下各连一次。
2. 每个节点都单独选中试一次，别只看 AUTO 能用。到了当地，主节点被干扰时，你得知道备用节点确实能连。
3. 在电脑上把 [防泄露检查](leak-protection.md) 至少做一遍，起码测 WebRTC 和 DNS。
4. 把本机账号页带在随身的设备上，别放进网盘的公开目录。订阅地址失效或者要换令牌时，你还要用它。
5. 记下服务商后台的网址和登录方式，需要时用来看流量或重启服务器。

到了当地以后：

- 同一台服务器，换个地方、换家运营商，速度可能差很多，这很正常。
- 连不上时，先换个网络试试（酒店 Wi-Fi、手机流量、另一家运营商），再在客户端里换个节点。
- 所有网络、所有节点都连不上，多半是服务器 IP 在当地被限制了。重装解决不了，要联系服务商换 IP，换好后重新部署、更新订阅。
- 线路只给自己和家人用，别分享给别人。订阅地址就是登录凭据，用的人越多，IP 越容易被盯上。
