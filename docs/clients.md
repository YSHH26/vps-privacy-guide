# 把手机和电脑连上

先打开本机账号 HTML，找到与你客户端对应的订阅。每条节点单独试过以后，再做 [IP 防泄露检查](leak-protection.md)。

三种订阅不一样：**Clash 订阅带分流规则**，国内网站直连、AI 服务单独一组、其他走代理；Surge 配置的 FINAL 全部指向代理，没有分流；v2rayN/v2rayNG 订阅只有节点，路由规则用客户端自己的。订阅都不会替你打开整台设备的 TUN，也不保证断线时不直连，这些要在客户端里设置后再检查。

## 按客户端导入

| 客户端 | 默认使用 | 导入办法 |
| --- | --- | --- |
| Clash Verge Rev（Windows / macOS / Linux） | Reality、VLESS TLS、AnyTLS | 在「订阅」里粘贴 Clash 订阅地址并导入，模式选「规则」，打开「虚拟网卡模式」 |
| OpenClash（软路由） | 同上 | 「配置订阅」里添加同一个 Clash 订阅地址，关闭「在线订阅转换」，内核选 Meta |
| Surge | AnyTLS | 取账号页中的 Surge 格式订阅，按当前版本的远程配置/代理列表功能添加 |
| v2rayN | VLESS Reality、VLESS TLS | 在订阅分组添加 HTTPS 地址并更新；也可粘贴 VLESS 分享链接 |
| v2rayNG | VLESS Reality、VLESS TLS | 在订阅设置添加 HTTPS 地址并更新；也可扫描节点二维码或导入链接 |

Surge 不依赖支持 VLESS 的测试版。客户端版本若不识别某个节点，先检查应用与核心能力；不要把未知协议硬塞进配置。AnyTLS 是否适合其他客户端，也以实际版本为准。以上是导入方向，具体菜单及最低实测版本要在真实设备上记录，未测试的版本不能承诺兼容。

节点订阅与完整 Surge 配置不同。如果下载的是代理列表，使用当前客户端对应的列表功能；不要直接覆盖现有整份配置。Clash/Mihomo 或 Shadowrocket 输出即使提供，也不能当作 Surge 配置导入；规则格式和语义需要分别校验。

添加后手动更新一次，逐条选中节点测试受控 HTTPS 地址，确认出口。测试时别用自动切换，避免一条坏节点被另一条掩盖。再分别记录 Windows / Android / Mac 等实际客户端和核心版本。

## Clash 订阅里有什么

导入后你会看到三个分组：

- **PROXY**：平时走代理的流量用它。默认选 `AUTO`，也可以手动指定某一个节点。
- **AUTO**：按 Reality → VLESS TLS → AnyTLS 的顺序，前一个连不上时换下一个。逐条测试节点时，在 PROXY 里手动选节点，不要停在 AUTO。
- **AI**：OpenAI、Claude、Gemini 等海外 AI 服务单独走这一组，默认跟随 PROXY。想让 AI 固定用某个节点，在这里选。

规则按这个顺序匹配：服务器自己的 IP 和局域网直连 → 海外 AI 服务走 AI → 国内域名和国内 IP 直连 → 其他全部走 PROXY。

DNS 用 fake-ip。境外域名用 Cloudflare / Google 的 DoH 查询，查询本身也经过代理；国内域名用阿里 / 腾讯的 DoH 直连查询。所有按 IP 匹配的规则都带 `no-resolve`，不会为了匹配规则先在本地查一遍，所以 DNS 泄露测试网站用的随机域名只会在代理那一侧被解析。代价是：没被收进国内名单的国内网站会绕道代理，仍能打开，只是慢一点。

规则数据（`geosite.dat`、`geoip.metadb`）由你的服务器每天从 MetaCubeX 的公开发布镜像一份，客户端只从你自己的服务器下载，路由器在国内也不需要直连 GitHub。下载或校验失败时服务器保留上一份。校验用的是同一来源发布的 sha256，只能发现传输损坏，不能证明上游内容可信。

两点要注意：

- AnyTLS 需要较新的 Mihomo 内核。生成的配置用固定的 Mihomo 1.19.33 检查过能正常解析；你实际用的 Clash Verge Rev / OpenClash 版本是否能连上，要在真机上记录。
- 规则模式加「虚拟网卡模式」（TUN）才能防住 WebRTC 泄露，只开系统代理不够，见 [WebRTC 泄露怎么修](webrtc.md)。Clash 设置里的 IPv6 开关保持打开：关掉后 IPv6 流量可能直接绕过虚拟网卡。配置里 DNS 不返回 IPv6 地址，服务器也拒绝转发到 IPv6，所以打开它不会让你从 IPv6 出去。

## 在线订阅要注意什么

HTTPS 使用 TCP 9443，后端仍在服务器回环。证书验证必须开启，IP 证书要能按 IP SAN 验证。Reality 占用 TCP 443，不能让 Nginx 再占同一端口。订阅地址含高熵随机令牌，能拿到链接的人可能拿到节点；链接外泄后需要轮换。

自动刷新时使用账号页中为该客户端生成的地址，不要把某一种格式改个后缀冒充另一种。订阅只在自己的服务上生成/转换，不使用第三方在线转换。分享链接、二维码和 HTML 同样都含秘密，不要上传。

节点连接地址应该是 VPS 公网 IP 或证书域名，不能是 `127.0.0.1`、Docker 地址或本机 SSH 隧道地址。如果地址不对，回到 S-UI 检查用户关联、入站发布地址、外部端口和客户端出站模板。

来源：[S-UI 订阅说明](https://github.com/alireza0/s-ui/wiki/Subscription-Service)。

## 用 sing-box 单独测试节点

[客户端模板](../examples/client.json) 只开放本机 `127.0.0.1:1080` 的 HTTP/SOCKS 代理，默认选 Reality。它不启用 TUN、自动切换、DNS 分流或故障阻断。

替换全部占位符，将 selector 的 `default` 分别改为 `reality`、`vless-tls`、`anytls`，每次重启后单独测试。两条 VLESS 使用同一 S-UI 用户的 UUID 和 Vision；Reality 填公钥、short ID、server_name 和 Vision，不能把服务端私钥放进客户端。VLESS TLS 和 AnyTLS 的证书身份须正确。

```sh
sing-box check -c private/client.json
sing-box run -c private/client.json
```

另开终端，用自己确认的 HTTPS 地址检查：

```sh
curl --proxy socks5h://127.0.0.1:1080 --max-time 20 https://example.com/
```

`socks5h` 把本次目标域名交给代理侧解析。这只能证明这个请求走了代理，其他程序、DNS、IPv6、WebRTC 和退出客户端后的表现还得各自测试。三个 TCP 节点能否转发 UDP 应用也要单测，不能从没有 UDP 入站监听得出结论。

## 出门前再检查一遍

如果你是要带着设备去网络受限的地方，**出发前**把下面几件事做完。到了当地，下载客户端、打开本仓库、访问服务商后台都可能变得困难。

1. 手机和电脑都装好客户端、导入订阅，在家里的网络下各自连一次。
2. 每个节点都单独选中试一次，不要只看 AUTO 能用。到了当地，主节点被干扰时你需要知道备用节点确实能连。
3. 在电脑上把 [防泄露检查](leak-protection.md) 至少做一遍 WebRTC 和 DNS。
4. 把本机账号页带在自己身边的设备上（不要上传网盘公开目录）。订阅地址失效或需要轮换时，你还需要它。
5. 记下服务商后台的网址和登录方式，必要时用来查看流量或重启服务器。

到了当地以后：

- 同一台服务器，换个地方、换家运营商，速度可能完全不一样，这很正常。
- 连不上时，先换个网络试试（酒店 Wi-Fi、手机流量、换一家运营商），再在客户端里换一个节点。
- 所有网络、所有节点都连不上，多半是服务器 IP 在当地被限制了。这不是重装能解决的问题，需要联系服务商更换 IP，换好后重新部署并更新订阅。
- 线路只给自己和家人用，不要分享给别人：订阅地址就是登录凭据，用的人越多，IP 越容易被注意到。
