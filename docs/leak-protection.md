# 连上以后，看看有没有漏 IP

不用一口气把所有检查都做完。找一台你平时用的手机或电脑，连上节点，从第一项开始往下做。

这里说的“漏 IP”，是你本来想让某些流量走代理，它却绕开了，直接从家里宽带或手机网络出去。你自己设成直连的网站看到本地 IP，这是正常的。

> 这一页目前只写了怎么检查。每个客户端里具体点哪个开关、填什么配置，要等真机测过以后再补上。仓库里的客户端模板只能用来测节点，不能直接当整台设备的防泄露配置用。

## 先留一个对照

先在没开代理的时候，记下你自己网络的公网 IPv4，有公网 IPv6 的话也记下。开了代理再对比，就能分清哪个是服务器的地址、哪个是你本地的。

完整地址只记在自己的私有笔记里。要把结果贴到 Issue 的话，写“出现了本地地址”就行，不用贴具体 IP。

## 1. 看看是不是只开了系统代理

系统代理一般只管那些愿意用它的软件。有些程序会自己联网，浏览器的一部分功能也可能走别的连接。

想让更多流量走代理，看看客户端有没有 **TUN** 或 **VPN 模式**。打开以后，还要看哪些应用被排除在外、哪些规则设成了直连、UDP 有没有被接管。

开关亮了，也不等于所有流量都进去了，后面的检查还是要做。

## 2. 查网址时，有没有走回本地网络

DNS 可以理解成“查一个网址对应哪个 IP”。网页本身走了代理，查地址这一步却可能还在用本地网络。

先看客户端的 DNS 设置，再看浏览器有没有自己开了安全 DNS。这两边走的可能不是同一条路。

测试时，显示出来的 DNS 服务应该和你的设置对得上。**DNS 的 IP 不一定是 VPS 的 IP**，看到不一样的地址先别急着认定是泄露；反过来，只看到国外的 DNS，也不能就算过关。

结果看不懂的话，先把客户端和浏览器的 DNS 设置记下来，再对照连接日志查。DoH 只是把查询加密了，说明不了这次查询一定走了代理。

## 3. 别漏掉 IPv6

有时候网页显示的 IPv4 已经是服务器的了，电脑却还在用本地的 IPv6 直接联网。

测试里出现了运营商分给你的公网 IPv6，这一项就还没配好。先看客户端有没有接管 IPv6；你的方案不走 IPv6 的话，就要在客户端或系统里拦住这部分流量，别让它从 IPv6 绕出去。

只把节点地址填成 IPv4，拦不住这部分流量。

服务器这边，代理出去的流量只走 IPv4：目标域名只解析成 IPv4 地址，直接连 IPv6 地址的请求会被拒绝。所以走了代理的流量不会有 IPv6 出口，网站也不会看到两个对不上的出口地址。但这管不到**没进代理**的流量，客户端那边还是要查。另外，测试里看到的地址不全是泄露：局域网地址、链路本地地址和 mDNS 名称都不是公网 IP。

## 4. 再看浏览器的 WebRTC

浏览器里的通话功能常用 WebRTC。它会通过 STUN 等方式查自己的公网地址，所以可能出现“网页 IP 是服务器，通话连接却带出了本地 IP”的情况。

检查时，看 WebRTC 结果里有没有你刚才记下的本地公网地址。有的话，先查 UDP 有没有走代理，再看浏览器允不允许不走代理的 UDP 连接。

有些浏览器可以限制这类连接。直接禁用 WebRTC 可能让通话功能用不了，要看你自己用不用；而且禁用它也管不了其他软件绕开代理。

出现了本地 IP，照 [WebRTC 泄露怎么修](webrtc.md) 一步步处理。最常见的原因是只开了系统代理，没开 TUN。

## 5. 故意让节点连不上，再试一次

节点连不上时，该走代理的流量应该停下来，不能悄悄变成直连。

可以复制一份临时的客户端配置，把节点端口改成一个连不上的端口，再测。之后还要分别看客户端退出、Wi-Fi 和手机流量来回切换、休眠后唤醒、重启设备时会怎样。

别为了这个测试把服务器的 SSH 或整台机器的网络关掉。先想好怎么改回来，每次只改一处。

每个客户端的断线保护都不一样，TUN 模式也不一定带这个功能。节点坏了，网页反而从本地网络打开了，就要继续调客户端或系统的拦截规则。

## 测完以后怎么记

不用写什么报告，把下面几项记清楚就行：

| 检查什么 | 希望看到什么 |
| --- | --- |
| 指定走代理的网页 | 使用预期的服务器出口 |
| IPv6 | 按设置走代理或被阻断，没有从本地绕出去 |
| DNS | 查询路径符合自己的设置，没有意外回落到本地解析 |
| WebRTC | 没有出现本地公网 IP |
| 节点故障、客户端退出 | 需要代理的流量停下来，没有转为直连 |
| 切网、重启、唤醒 | 重新检查，结果仍符合上面的要求 |

记上测试日期、客户端版本和用的是什么网络。先把这一台设备测完，再换下一台。这次过了，换设备或升级以后还是要重新测。

这些检查只是看流量有没有走错路。运营商还是知道你连着 VPS，VPS 服务商手里有你的账户信息，你登录的网站也照样认得你的账号。

想了解技术细节，可以看 [sing-box TUN 文档](https://sing-box.sagernet.org/configuration/inbound/tun/) 和 [MDN 对 WebRTC、STUN 的解释](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Protocols)。
