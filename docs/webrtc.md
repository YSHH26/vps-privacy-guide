# WebRTC 泄露怎么修

检测网站上，网页 IP 已经是服务器了，WebRTC 那一栏却显示你家宽带或手机网络的公网 IP。这一页讲怎么修，修完怎么确认。

> 下面的菜单名称是照常见版本写的，还没在真机上逐个核对，你看到的位置可能有点不一样。修完一定要按第 4 步实际检查一遍，以检查结果为准。

## 1. 先留一个对照

先**关掉代理**，打开一个能显示 WebRTC 结果的检测页面（例如 browserleaks 的 WebRTC 页），记下「Public IP Address」一栏的地址。这是你本地网络的公网 IP，后面拿它来比对。

完整地址只记在自己的私有笔记里，不要贴到 Issue 或群里。

## 2. 为什么会漏

浏览器里的视频通话、会议软件网页版都用 WebRTC。它会主动向 STUN 服务器询问「我的公网地址是什么」，这一步用的是 **UDP**。

「系统代理」只接管愿意使用它的程序发出的 TCP 连接（主要是普通网页）。WebRTC 的 UDP 请求不经过系统代理，直接从本地网络出去，检测网站就看到了你的真实 IP。

所以要改的是客户端：它只开了系统代理，服务器和订阅都不用动。要让 UDP 也走代理，得打开客户端的 **TUN**（有的客户端叫「虚拟网卡模式」或「增强模式」）。TUN 会在系统里建一块虚拟网卡，所有流量先进客户端，再按规则决定直连还是走代理。

## 3. 按你的客户端打开 TUN

### Clash Verge Rev（推荐）

1. 导入本仓库生成的 Clash 订阅，模式选 **规则**。
2. 打开 **虚拟网卡模式**。第一次会提示需要安装服务，按提示安装（Windows 会弹出权限确认，macOS 要输入开机密码）。
3. Windows：点虚拟网卡模式旁边的设置，打开 **严格路由**，防止部分流量绕开虚拟网卡。
4. 设置里的 **IPv6** 开关保持打开。关掉后，IPv6 流量可能直接从虚拟网卡旁边绕出去。我们的订阅不让 DNS 返回 IPv6 地址，服务器也拒绝转发到 IPv6，所以打开它不会让你从 IPv6 出去。
5. 不要打开「DNS 覆写」。订阅里已经带了防泄露的 DNS 设置，覆写会替换掉它。
6. 「系统代理」开着或关着都可以，TUN 已经接管了流量。

### Surge

打开 **增强模式**（Enhanced Mode）。Surge 用的是本仓库的 AnyTLS 配置，规则是全部走代理。

### v2rayN

打开 **TUN** 模式，路由选「绕过大陆」或你需要的规则。v2rayN 订阅里只有节点，没有分流规则。

### 手机

iOS 和 Android 上的代理客户端一般本身就以 VPN 方式运行，所有应用的流量都会进入客户端。修改了「按应用分流」或「绕过某些应用」的，要确认浏览器不在绕过名单里。

## 4. 修完以后检查

1. 关掉浏览器再重新打开（已经建立的 WebRTC 连接不会自动换路线）。
2. 打开同一个 WebRTC 检测页。
3. 看「Public IP Address」：
   - 显示的是**服务器 IP**：修好了。
   - 仍然显示第 1 步记下的本地 IP：TUN 没有生效，回到第 3 步检查是否真的打开、服务是否安装成功。
   - 什么都不显示：通常说明 UDP 没走通，WebRTC 应用（网页通话）可能用不了，但没有泄露。可以继续排查客户端的 UDP 设置。
4. 看到局域网地址（`192.168.x.x`、`10.x.x.x`）或一串 `.local` 名称是正常的，这些不是公网 IP，不算泄露。

再顺便看一下 DNS 检测：显示的 DNS 服务器不应该出现你本地运营商的 DNS。详细方法见 [防泄露检查](leak-protection.md)。

## 不建议直接禁用 WebRTC

装插件或改浏览器设置把 WebRTC 关掉，确实不会再漏 IP，但网页版视频会议、在线通话会直接不能用。而且它只管浏览器，电脑上其他会自己联网的程序照样可能绕开系统代理。

打开 TUN 以后，流量都先进客户端，WebRTC 照常能用，出口变成你的服务器。

## 换设备、升级后要重新检查

这次检查只代表这一台设备、这个客户端版本、这个浏览器。换设备、升级客户端、换浏览器以后，重新按第 4 步检查一遍。把日期、客户端版本和结果记下来，未检查的写「未测试」。
